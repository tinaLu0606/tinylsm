# TinyLSM read-path performance report

Status: completed on 2026-09-07. This report records the Goal 1 acceptance
measurements, not a general-purpose throughput claim.

## Measurement contract

The Release suite uses deterministic 16-byte keys and 100-byte values. Setup is
outside the manually timed interval; every case uses a fresh DB, five
repetitions, and reports its median and coefficient of variation (CV).

- MemTable hit; one-SSTable hit; four overlapping-range SSTable oldest-table
  hit; and an in-range miss that must probe four tables.
- A 256-key repeated hit and 20 scans of 10,000 SSTable-backed entries.
- A fixed total of 40,000 SSTable hits with 1, 2, 4, and 8 readers.

The four-table layout uses interleaved keys: Manifest ranges overlap, but each
key is in exactly one table. It therefore exercises real table and block probes,
unlike an out-of-range miss rejected by Manifest metadata.

## Fixed-Linux profile and decision

The fixed Ubuntu 24.04 ARM64 Lima VM used a guest-local ext4 disk, 4 vCPU, and
8 GiB RAM. Lima/VZ does not expose hardware PMU events, so Linux `perf 6.8.12`
used software `cpu-clock` at 499 Hz with DWARF call graphs. The VM's dedicated
`kernel.perf_event_paranoid` setting was temporarily changed from 4 to 1.

`ReadRandomHit` collected 21,000 samples with none lost: `Crc32c` was 92.30%
of self samples, on `DB::Get -> SSTableReader::ReadBlock -> DecodeDataBlock ->
Crc32c`. The corrected four-SSTable `ScanProfile` (cache disabled) collected
2,000 samples; `Crc32c` was 87.25% self, on `Iterator::LoadBlock ->
MergingIterator::Next -> DB::Impl::Scan`. This supports caching already
validated decoded blocks; it does not support skipping checksum validation.

## Implemented bounded Block Cache

`Options::block_cache_bytes` defaults to 8 MiB; setting it to zero disables the
cache. Entries are LRU-managed, owned decoded blocks keyed by `(table number,
block offset)`. A miss reads, checks CRC and structure, decodes, and validates
sequence metadata before insertion. Failed reads never populate the cache.

The cache charges entries against its limit and evicts LRU entries. Compaction
removes entries belonging to replaced table numbers after the committed reader
swap. `DB::GetReadMetrics()` exposes cumulative probe/read/decode/cache and
read/write lock counters; benchmark values are setup-subtracted snapshots.

Read synchronization is now:

```text
Get / Scan / diagnostic snapshot -- shared DB mutex --> cache mutex
Put / Delete / Write / Compact / Close -- unique DB mutex --> cache mutex
```

There is no cache-to-DB acquisition path. A Scan holds its shared lock while it
materializes the result, so it can delay a writer; this is intentional lifetime
protection, not snapshot isolation.

was 15,780 KiB, versus 15,664 KiB before; this process-level delta is not a
standalone cache-memory measurement, while the cache charge is bounded and
directly measured.

## Bloom-filter decision and verification

Bloom filters are not implemented in Goal 1. The in-range negative lookup was
explicitly measured and is accelerated by the validated block cache from about
2.57k to 670k ops/s. Post metrics show the remaining warm work is cache lookup
and table probing, not repeated decode/CRC; adding a new per-table metadata
format now would not be evidence-led. Revisit it only after a workload whose
negative lookup cost remains material with the cache enabled.

Correctness and resource tests cover disabled mode, failed-read non-insertion,
LRU charge eviction, compaction table-entry removal, and two independent
SSTable Gets reaching a gated read concurrently. Local format checking and the
full Debug suite passed; fixed Linux additionally passed 101/101 in Debug,
ASan/UBSan, and Clang TSan, plus the Release build and both benchmark runs.
