# 2026-09-08 · TinyLSM · Devlog

## Goal 3 · Compaction metrics and background partial compaction

状态：`进行中`

### 已完成并验证

- 选择简化 size-tiered 策略：达到默认四张 SSTable 时，单 worker 合并最老、连续的
  四张表；`Options::compaction_table_trigger = 0` 可关闭自动调度。
- 新增可复算原始指标：point lookup、range scan、scan table input、logical write
  bytes、flush/compaction physical SSTable bytes、input/output table count、live
  SSTable bytes 和 table/byte compaction debt。报告须从这些原始计数计算放大率。
- background worker 继续优先 flush；flush 发布后只在 debt 存在时调度一个 compaction
  job，不 busy-loop。后台 job 先 durable 地保留 output file number，再在锁外读取
  shared SSTable reader snapshot；flush/compaction 的 Manifest publication 均由同一
  state lock 串行化。
- partial job 仅替换最老表前缀，因此没有未参与的更旧值；输出可安全删除该前缀中的
  tombstone。较新的 MemTable/SSTable 仍以更高 sequence 覆盖输出。
- explicit `Compact()` 保留原有“持独占锁、单次 Manifest commit”的恢复边界；它会
  等待已排队的后台工作后重写当时的完整 table set。

### 验证证据

- `./run format --check`、`./run test dev-debug` 和 `git diff --check` 通过；完整
  Debug suite 为 `107/107`，其中本阶段新增五项 background compaction 测试。
- `BackgroundCompactionTest.DropsOnlySafeOldestPrefixTombstoneAndReportsRawMetrics`
  验证两表 tombstone merge 后旧值不会复活，且 table/debt/byte counters 合理。
- `BackgroundCompactionRecoveryTest.FailedCommitKeepsTheOldestPrefixRecoverable`
  在 output Manifest rename 前注入失败：worker 进入 sticky error，reopen 从旧表集
  读回完整数据。
- `BackgroundCompactionConcurrencyTest.ReaderCanOverlapTheCompactionInputSnapshot`
  用文件读取 gate 证明 foreground Get 与后台 compaction input 同时到达 I/O gate，
  再验证 compact 后 Scan 仍完整。
- `BackgroundCompactionTest.LongMixedWorkloadMatchesReferenceAcrossReopen` 使用
  5,000 次 Put/Delete/Get/Scan 与 `std::map` reference 对照，并在 reopen 后复验。
- `TinyLSM/CompactionMixedManual` 与 `TinyLSM/CompactionMixedSizeTiered` 都完成
  本机 Release smoke；五轮 case 记录 logical/live/physical byte、table/debt、
  read/write/space amplification 和 Put/Get/Scan tail。固定 Linux 原始 JSON 仍未做。
