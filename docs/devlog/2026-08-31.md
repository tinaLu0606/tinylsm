# 2026-08-31 · TinyLSM · Devlog

## V2.1 Manifest 发布故障恢复

状态：`已验证`

### 完成

- 为 Manifest 发布增加 `kNotPublished`、`kVisibleNotDurable` 和 `kDurable`
  三种内部结果，区分 rename 前失败与 rename 后目录同步失败。
- Manifest 只有在 rename 和 `SyncDir` 全部成功后才更新内存 snapshot。
- Manifest rename 成功但 `SyncDir` 失败时，`DB::Impl` 保存 terminal error；当前
  实例拒绝后续 Get/Put/Delete/Scan，要求用户 Close 后重新 Open。
- `Close()` 只报告本次 WAL 同步和关闭结果；即使数据库已处于 terminal 状态，
  Close 自身成功仍返回 `OK`。
- 将数据库 Open 流程拆为目录准备、Manifest 读取/创建、SSTable 打开和 WAL
  恢复步骤，保留原有恢复顺序与错误上下文。
- 新增按操作、路径、调用次数和调用前后时机匹配的测试文件系统，并将 TempDir
  和已有错误测试接入统一的 `tests/test_support`。
- 新增 flush recovery tests，覆盖 SSTable、新 WAL、Manifest 各发布阶段失败、
  terminal 状态、重新打开恢复，以及 commit 后旧 WAL 清理失败。

### 验证

```bash
cmake --build --preset dev-debug
ctest --preset dev-debug
cmake --preset dev-asan-ubsan
cmake --build --preset dev-asan-ubsan
ctest --preset dev-asan-ubsan
cmake -S . -B build/release-tests -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON -DTINYLSM_BUILD_TOOLS=ON
cmake --build build/release-tests
ctest --test-dir build/release-tests --output-on-failure
./scripts/format.sh --check
git diff --check
```

- Debug：`29/29` tests passed。
- Release：`29/29` tests passed。
- ASan + UBSan：`29/29` tests passed，未发现 sanitizer 报错。
- clang-format 和 `git diff --check` 通过。
- 构建仍会显示 Protobuf/Abseil 的第三方 CMake 弃用 warning；未发现 TinyLSM
  自身新增的编译错误。

### 当前边界与下一步

- recovery tests 验证系统调用故障注入和立即 reopen，不等同于真实掉电实验。
- V2 仍最多发布一个 SSTable；多 SSTable、compaction 和后台 flush 未实现。
- CLI 当前只支持读取已有 key；Put/Delete/Scan 仍通过 C++ `DB` API 和测试使用。
- 下一步可先进行 Linux 文件语义验证，再单独设计 V3 多 SSTable。
