# 2026-09-04 · TinyLSM · Devlog

## V3 阶段三：内部 Iterator 与归并 Scan

状态：`已验证`

### 完成

- 新增仅供存储模块使用的 `InternalIterator`，统一 `Valid()`、`entry()`、
  `Next()` 和 sticky `status()` 合同。
- MemTable iterator 直接借用有序 map；SSTable iterator 使用 index 定位首个
  block，并且一次最多保留一个解码后的 data block。
- 新增拥有所有输入的 `MergingIterator`，按 byte-wise key 排序，为重复 key
  选择最大 sequence，并拒绝相同 key/sequence 的损坏状态。
- `DB::Scan()` 改为消费归并 iterator，过滤 tombstone；只有正常到达 EOF 才
  返回物化结果，后续 block 的 IO/CRC 错误不会产生部分成功结果。
- SSTable 单 block 读取现在同时核对 index 首尾 key 和非零 sequence，避免
  iterator 路径绕过已有数据校验。

### 测试

- 新增 MemTable 半开范围与 binary byte-wise 顺序测试。
- 新增多路归并 winner、tombstone、重复 sequence 和 sticky error 测试。
- 新增 SSTable 惰性跨 block 读取故障，以及 public Scan 不返回部分结果测试。
- Debug：`61/61` tests passed。
- ASan + UBSan：`61/61` tests passed；sanitizer 在实现过程中曾发现归并器
  current-group 容器复用问题，修正所有权表示后全量复验通过。
- clang-format、clang-tidy 和 `git diff --check` 通过；clang-tidy 仅保留仓库
  原有告警。

### 边界与下一步

- public `Scan()` 仍按既有 API 返回 `vector<Entry>`；惰性只存在于内部来源与
  归并阶段。
- 下一步复用同一归并 iterator 实现显式同步 full compaction。
