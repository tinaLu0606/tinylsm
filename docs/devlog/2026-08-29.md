# 2026-08-29 · TinyLSM · Devlog

## 错误与异常处理强化

状态：`已验证`

### 完成

- 确立混合错误边界：可预期的参数、I/O、数据损坏和能力限制继续通过
  `Status`/`Result<T>` 返回；`std::bad_alloc`、标准库及依赖异常不在核心库中
  统一吞掉，可传播到应用边界。
- 为 `Status` 增加 `kResourceExhausted`、`WithContext()`、`ToString()`、
  `IgnoreError()` 和 `[[nodiscard]]`，并限制调用方直接构造任意状态码。
- 强化 `Result<T>` 不变量：失败结果不能携带 `OK`；`value()` 在所有构建模式
  下都会检查状态并抛出 `BadResultAccess`；增加 `operator*` 和 `operator->`。
- 将 `FileSystem::FileExists()` 改为 `Result<bool>`，区分路径不存在与权限、路径
  过长等检查失败；POSIX 错误在系统调用后立即保存 `errno`，避免诊断漂移。
- 为数据库打开、WAL 恢复、SSTable 校验、Manifest 发布和 flush 等路径补充操作
  上下文，同时保持原始 `StatusCode` 不变。
- 明确 `DB::Close()` 状态转换：WAL sync 失败时数据库保持打开并可重试；一旦
  已尝试关闭底层文件，数据库进入关闭状态，即使 close 本身返回错误。
- CLI 已实现最外层异常边界，分别处理 `BadResultAccess`、`std::bad_alloc`、
  `std::exception` 和未知异常；核心库未引入 spdlog。
- 增加轻量可注入 `FileSystem` 测试接缝，覆盖 exists、sync、close、标准异常传播
  和 sequence 耗尽等错误路径；测试总数由 14 增加到 21。
