# 2026-08-25 · TinyLSM · Devlog

## V0–V2 存储引擎实现

状态：`已验证`

### 完成

- 实现公开 `DB` API、`Status`/`Result<T>`、`Options` 和扫描结果类型。
- 完成带 sequence、空 value 和 tombstone 语义的有序 MemTable。
- 完成 POSIX 文件抽象、CRC32C、WAL 编解码与恢复；合法截断尾部可恢复，中部损坏返回 `kCorruption`。
- 完成多 data block SSTable、index/footer 独立校验、随机 Get 和范围 Scan。
- 完成 Protobuf Manifest payload、外层 framing/CRC 和 temp → sync → rename → SyncDir 原子发布。
- 在 `DB::Impl` 串联 WAL-first 写入、同步首次 flush、Manifest 恢复，以及一个 SSTable 与当前 MemTable 的 Get/Scan 合并。
- 增加 CLI、单元测试和集成测试；V2 在产生任何新写入前拒绝第二次 flush。

### 错误契约与注释

- 为公开 `DB` API、`Options`、`Status`、`Result<T>` 和 `Entry` 增加英文接口注释。
- 为 MemTable sequence/tombstone、文件句柄 short read/write、WAL 截断恢复、SSTable 顺序与 checksum、Manifest 发布提交边界增加英文契约注释。
- 当前约定：可预期的参数、I/O、数据损坏和能力边界错误通过 `Status` 或 `Result<T>` 显式返回；`std::bad_alloc` 等非预期 C++ 异常未被统一捕获。
- 当前 `Result<T>::value()` 要求先检查 `ok()`，错误访问只在 Debug 下由 `assert` 防护；`Put/Delete` 返回错误也不保证前序 WAL/MemTable 修改未发生。

### 验证

```bash
cmake --build --preset dev-debug -j 4
ctest --preset dev-debug
cmake --build --preset dev-asan-ubsan -j 4
ctest --preset dev-asan-ubsan
git diff --check
```

- Debug：`14/14` tests passed。
- ASan + UBSan：`14/14` tests passed。
- `git diff --check` 通过。
- 构建仍有来自 Protobuf/Abseil 依赖的 7 条 Apple Clang 兼容性 warning；未发现 TinyLSM 测试失败或 sanitizer 报错。

### 当前限制与下一步

- V2 仍只支持一个已发布 SSTable；多 SSTable、compaction、immutable MemTable 和后台 flush 尚未实现。
- `未做`：强化 `Result<T>` 的 Release 模式不变量、为返回结果增加 `[[nodiscard]]` 防误用、补充状态上下文/字符串化，以及定义公共 API 对非预期 C++ 异常的边界策略。
